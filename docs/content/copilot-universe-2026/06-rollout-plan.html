The previous lessons covered the individual features. This lesson covers the decisions a team makes when adopting them: what to turn on, for whom, in what order, and at what cost. It works through a plan for a fictional company, and covers the last Universe announcement, which is about pricing: GitHub Enterprise now includes access to Copilot.

Key point Nearly every new Copilot feature spends AI credits, and several act with no prompt from a person. Set budgets and policies first, then turn features on, lowest risk first.

The scenario

Acme has 200 engineers on GitHub Enterprise Cloud and about 40 contractors without Enterprise licences. It has a monorepo and 30 service repos, runs CI on GitHub Actions with some self-hosted runners, and its security team requires a person to approve any change to auth or payments code. Acme doesn't use Copilot yet.

Step 1: understand the costs

Since 1 June 2026, Copilot usage has been measured through licences plus AI credits, which third-party sources report as worth $0.01 each. Only some older annual Pro and Pro+ plans are still on premium-request billing. Code completions and next edit suggestions don't use credits on paid plans. Chat, Copilot CLI, the cloud agent, code review and third-party coding agents do. Cloud sandbox usage is billed from November 2026 out of the included Actions entitlement, which is now one dollar-based pool shared with CI runners.

Enterprise-included access

At Universe, GitHub announced that GitHub Enterprise now includes Copilot access for every licensed user, so a separate Copilot subscription isn't needed. It has the same features and models as Copilot Enterprise. You pay for the AI credits you use.

It's currently available only to GitHub Enterprise Cloud customers who work with a GitHub or Microsoft account team. Self-serve customers can't get it yet. GitHub says it will announce self-serve dates in the coming weeks. Copilot Business and Copilot Enterprise remain on sale, and existing customers can keep their plans or switch.

Warning A $0 seat doesn't mean Copilot is free. With no included credits, a heavy agent user can cost more than a $39 seat would. Enterprise-included access is usually cheaper when many people use Copilot lightly, and more expensive when a few people use it heavily. Estimate your own usage before switching.

Acme has no Copilot seats and works with a GitHub account team. It chooses Enterprise-included access for the 200 engineers and Standalone for the 40 contractors, and sets an enterprise budget and alerts before anyone starts.

Step 2: set policies

These are the controls covered in this topic:

Default modelMake Fusion Standard the default, so High and Max are used deliberately.

Approval pathsApprovals are off by default. When on, limit which file paths Copilot may approve.

Acme's security team allows models from two providers, so Fusion's Cascade and Critique patterns and code review Max have more than one provider's models to use. It disables computer use for now.

Step 3: turn features on, lowest risk first

  1. Week 1: assistanceCompletions, chat and Fusion at Standard in VS Code and JetBrains. Low risk, and it gives a baseline for credit spend.
  2. Week 2: reviewCopilot code review at Balanced on all repos, comments only. Compare its findings with human reviewers'.
  3. Week 3: approvals and Agent MergeCopilot approvals turned on only for docs and test paths. Agent Merge is opt-in per PR via Watch and fix.
  4. Week 4: automationOne Agentic Workflow for issue triage, with read-only permissions and the add-comment safe output, on self-hosted runners.
  5. Later: previewsOne team trials Projects and code review Max, noting that their behaviour may change.

Each step depends on the previous one. You can't judge whether Copilot's approvals are reliable until you've seen its reviews, and agents shouldn't open PRs at scale until review and merge are controlled.

Step 4: set up PR guardrails

For payments and auth code, Acme requires a person to approve:

# .github/CODEOWNERS
/services/payments/   @acme/payments-owners
/services/auth/       @acme/security
/docs/                @acme/docs

A few things to notice:

  • Branch protection requires CODEOWNER review, so a Copilot approval alone can't merge a payments change. Copilot also isn't allowed to approve those paths.
  • /docs/ is on Copilot's approved-paths list. The team decides that Copilot's approval plus passing CI is enough there, and auto-merge does the rest.
  • Any push dismisses Copilot's approval, so a fix from Agent Merge triggers a new review.

Step 5: measure and adjust

After a month, Acme checks three things: credit spend by feature (which features cost most), review usefulness (what share of Copilot's comments people acted on), and how long agent-authored PRs take to merge. If a few Max sessions account for most of the spend, they lower the default effort. If the reviews are useful, they consider Max on the payments repo, where a missed bug costs most.

Note Preview features change quickly after a launch. Recheck the GitHub changelog in a month for Projects, code review Max, computer use and connectors, and update your policies when they leave preview.

Takeaways

  • Copilot bills on licences plus AI credits (reported as $0.01 each). Completions and next edit suggestions don't use credits on paid plans. Agent features do.
  • GitHub Enterprise now includes Copilot access: $0 seats, no included credits, and charges from the first request. Standalone is $10 a month for other users. For now it's only available through an account team, and Business and Enterprise plans remain on sale.
  • Set budgets and policies (models, default model, review cap, approval paths, computer use, cloud policies, automation limits) before turning features on.
  • Turn features on lowest risk first: assistance, then review, then approvals and Agent Merge, then automation, then previews.
  • Branch protection and CODEOWNERS determine what Copilot's approval allows. Keep human approvers on sensitive paths.
