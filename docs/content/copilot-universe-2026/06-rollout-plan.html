You've now seen every piece: Fusion picks the models, the shared harness runs agents anywhere, Projects coordinate them, code review and Agent Merge close out the pull requests, and Automations and Agentic Workflows run jobs on their own. The question a team actually faces on Monday morning is different: what do we switch on, for whom, and what will it cost?

This capstone works through that as a concrete plan for a fictional company. Along the way it covers the last big Universe announcement, which is about money: GitHub Enterprise now includes access to Copilot.

Key idea Nearly every new Copilot capability spends AI credits, and several act without a human prompt. A good rollout sets budgets and policies first, then turns features on in order of risk.

The scenario

Acme has 200 engineers on GitHub Enterprise Cloud and about 40 contractors who don't have Enterprise licences. They run a monorepo plus 30 service repos, CI on GitHub Actions with some self-hosted runners, and a security team that wants a human sign-off on anything touching auth or payments. Today they don't pay for Copilot at all.

Step 1: understand the bill

Since 1 June 2026, Copilot usage has been measured through licences plus AI credits, widely reported as worth $0.01 each. Only some legacy annual Pro and Pro+ plans are still on the old premium-request billing. Code completions and next-edit suggestions don't consume credits on paid plans. Chat, Copilot CLI, the cloud agent, code review and third-party coding agents do. Cloud sandbox usage is billed from November 2026 and draws from your included Actions entitlement, which is now one dollar-based pool shared with your CI runners.

The new Enterprise option

At Universe, GitHub announced that GitHub Enterprise now includes access to Copilot for every licensed user, so you no longer buy a separate Copilot subscription. You get the same features and models as Copilot Enterprise, and you pay for the AI credits you use:

Seat price$0 for users with a GitHub Enterprise licence$19 (Business) or $39 (Enterprise) per user per month

Users without an Enterprise licenceCopilot Standalone at $10 per user per month, with the same accessNormal seats

Availability is the catch. Right now it's only for GitHub Enterprise Cloud customers who work with a GitHub or Microsoft account team. For self-serve customers it's currently unavailable, with dates promised "in the coming weeks". Copilot Business and Copilot Enterprise are still on sale, and existing customers can keep their plans or move over.

Gotcha "$0 seat" isn't "free". With no included credits, a heavy agent user can easily cost more than a $39 seat would have. Enterprise-included access tends to save money when many people use Copilot lightly, and costs more when a few people use it heavily. Model your own usage before you switch.

For Acme, which has no existing Copilot seats and talks to a GitHub account team, Enterprise-included access for the 200 engineers plus Standalone for the 40 contractors is the natural start. They set an enterprise budget and alerts before anyone starts using it.

Step 2: set policies before features

Here are the controls from this topic, gathered in one place:

Model policiesChoose which models are allowed. Fusion only routes to allowed models.
Default modelMake Fusion Standard the default, so High and Max are a deliberate choice.
Review effort capCap code review at Balanced org-wide, and allow Max on chosen repos.
Approval pathsApprovals are off by default. When you turn them on, limit which file paths Copilot may approve.
Computer useOpt-in preview. Disable it in managed settings until you've assessed it.
Cloud policies"Copilot in the cloud" for cloud sessions, and "Allow use of Copilot cloud agent billed to the organization" for shared automations.
Automation limitsAI credit caps per run, day, week or month on each automation.
Branch protectionNot a Copilot setting, but the one that decides what Copilot's approval is worth.

Acme's security team allows models from two providers, which gives Fusion's Cascade and Critique patterns and code review Max's multi-provider design something to work with, and disables computer use for now.

Step 3: turn things on in order of risk

  1. Week 1: assistanceCompletions, chat and Fusion at Standard in VS Code and JetBrains. Low risk, and it shows the baseline credit burn.
  2. Week 2: reviewCopilot code review at Balanced on all repos, comments only. Compare its findings with human reviewers.
  3. Week 3: approvals and Agent MergeCopilot approvals are turned on only for docs and test paths. Agent Merge is opt-in per PR via Watch and fix.
  4. Week 4: automationOne Agentic Workflow for issue triage, with read-only permissions and the add-comment safe output, on self-hosted runners.
  5. Later: previewsPilot Projects and code review Max with one team, and treat their statuses as subject to change.

The order matters. Each step relies on the one before: you can't judge whether Copilot's approvals are trustworthy until you've seen its reviews, and you shouldn't let agents open PRs at scale until review and merge are under control.

Step 4: wire the PR guardrails

For the payment and auth paths, Acme keeps a human in the loop:

# .github/CODEOWNERS
/services/payments/   @acme/payments-owners
/services/auth/       @acme/security
/docs/                @acme/docs

A few things to notice:

  • Branch protection requires CODEOWNER review, so a Copilot approval alone can't merge a payments change. And Copilot isn't allowed to approve those paths in the first place.
  • On /docs/, which is on Copilot's approved-paths list, the team decides that Copilot's approval plus green CI is enough, and auto-merge does the rest.
  • Because any push dismisses Copilot's approval, an Agent Merge fix-up triggers a fresh review instead of slipping through.

Step 5: measure and adjust

After a month, Acme looks at three things: credit spend by feature (is code review or cloud agent the big line?), the review signal (what share of Copilot's comments did humans act on?) and the merge time for agent-authored PRs. If spend is dominated by a handful of Max sessions, they tighten the default effort. If reviews are useful, they consider Max on the payments repo, where a missed bug costs the most.

Tip Statuses shift fast after a conference. Put a reminder in the calendar to recheck the GitHub changelog in a month for Projects, code review Max, computer use and connectors, and update your policies when they leave preview.

Takeaways

  • Copilot bills on licences plus AI credits (reported as $0.01 each). Completions and next-edit suggestions are free on paid plans, and agentic features aren't.
  • GitHub Enterprise now includes Copilot access: $0 seats, no included credits, and metering from the first request. Standalone is $10 a month for others. For now it's only available through an account team, and Business and Enterprise plans stay on sale.
  • Set budgets and policies (models, default model, review cap, approval paths, computer use, cloud policies, automation limits) before switching features on.
  • Roll out in order of risk: assistance, then review, then approvals and Agent Merge, then automation, then previews.
  • Branch protection and CODEOWNERS decide what Copilot's approval is worth. Keep humans on sensitive paths.
