After the code is written, a pull request often waits on routine work. CI fails on a lint rule. After that's fixed, a flaky integration test fails. Someone merges to main and the lockfile conflicts. Then the PR waits for a reviewer.

When agents open more pull requests (see Projects in the previous lesson), this stage takes up a larger share of the time. Two Universe 2026 features address it: Agent Merge, which fixes the blockers that stop a PR merging, and changes to Copilot code review, which gained a multi-agent level and can now approve pull requests.

Key point Code review assesses whether a change is correct. Agent Merge fixes what stops it merging. With auto-merge and branch protection, they can take a PR from ready to merged, with people setting the rules rather than doing each step.

Agent Merge

Agent Merge watches a pull request and fixes blockers to merging. GitHub names two: failing GitHub Actions workflows and merge conflicts. It was already in the Copilot app and VS Code. At Universe it was added to pull requests on github.com.

  1. Turn it onIn the PR's merge box, choose Watch and fix.
  2. Choose what it handlesCI failures, merge conflicts, or both.
  3. A blocker appearsA workflow fails, or main changes and causes a conflict.
  4. Copilot fixes itIt works in a cloud development environment and pushes a fix to the branch.
  5. MergeWith auto-merge on, GitHub merges once every requirement is met.

You can also turn Agent Merge on for all your pull requests in your Copilot settings. It's available on paid Copilot plans, subject to organisation and enterprise policies.

Warning A failing check can be made to pass in the wrong way, for example by deleting a test, loosening an assertion or skipping it. Agent Merge pushes commits to your branch, so review what it changed, not only that CI passed. Keep required reviews and CODEOWNERS on important paths.

Code review effort levels

Copilot code review has had effort levels since August 2026. As with Fusion, you choose how much work to spend, not which model.

LevelHow it reviewsStatus
LiteAn ensemble of agents, since SeptemberGA
BalancedThe default for new and existing repos and organisations since 2 OctoberGA
MaxSeveral independent review agents on models from different providers, combined by an aggregation agentPublic preview (new at Universe)

How Max works

Several review agents review the pull request independently. They use models from different providers, because each model has different blind spots. An aggregation agent then reconciles their findings, resolves disagreements and checks accuracy before producing one review. You get one set of comments, not several overlapping ones.

GitHub recommends Max for higher-risk changes, such as authentication logic or a shared library that several services depend on. Max takes longer and uses more AI credits than Lite or Balanced. GitHub hasn't published how many agents a Max review uses or what a typical review costs, so test it on some real PRs before making it a default.

Choosing and capping effort

You can choose Max for one pull request from the Reviewers bar, or set it as the default review effort for a repository, organisation or enterprise. Each level can override the one above it.

Admins can set a maximum effort level at the enterprise, organisation or repository level. Levels above the maximum aren't available. Use this to stop every PR in a busy monorepo running a Max review.

Code review Max and approvals are available on Copilot Pro, Pro+, Max, Business and Enterprise.

Copilot approvals

Copilot code review can now approve pull requests as well as comment on them. This was a public preview from September and became generally available at Universe. Every review includes an approval assessment in the pull request overview comment, stating whether Copilot considers the PR ready to merge. When approvals are on, Copilot can approve, and its approval counts toward the repository's required approvals in the same way as a person's.

  • Approvals are off by default. Admins turn them on at the enterprise, organisation or repository level.
  • Repository admins can choose which file paths Copilot is allowed to approve.
  • If new commits are pushed after Copilot approves, its approval is dismissed, as a person's would be, and you request a new review. This includes commits from Agent Merge.
Note Whether a Copilot approval should count is a policy decision. One option is to let Copilot approve low-risk paths (docs, tests, generated code) using the path setting, and require a human CODEOWNER on sensitive paths (auth, billing, infrastructure). GitHub suggests using Max with approvals on the repositories where a missed issue costs most.

ReviewBench

GitHub's Universe post said code review Max "posted the highest F1 score on ReviewBench for high-severity issues". ReviewBench is GitHub's own benchmark for AI code review. It uses 219 public pull requests from 187 public repositories in 19 languages. On GitHub's leaderboard, Copilot code review at Balanced scored a 40.1% grounded F1.

Independent coverage raised two caveats. Copilot supplied 1,185 of the 2,623 true-positive findings in the benchmark's answer key, which may favour Copilot. And on a separate, independent benchmark, Copilot code review ranked fifth in early October. Use the vendor benchmark as one data point and judge the reviews on your own pull requests.

Combining the features

This is one way a team might set up both features with guardrails:

  1. An agent opens a PRFrom a Project, an Automation or a person.
  2. Code review runsBalanced by default. Max on high-risk PRs, within the admin cap.
  3. Agent Merge watchesFixes CI failures and conflicts. Each push dismisses the earlier approval.
  4. Rules applyCopilot may approve only low-risk paths. Branch protection requires a human CODEOWNER elsewhere.
  5. Auto-mergeMerges when every requirement is met.

Takeaways

  • Agent Merge ("Watch and fix" in the merge box) fixes failing Actions workflows and merge conflicts in a cloud environment. It's on paid plans and works with auto-merge.
  • Code review effort levels are Lite, Balanced (the default since October) and Max, a public-preview review using several providers' models and an aggregation agent.
  • Admins can cap review effort at the enterprise, organisation or repository level.
  • Copilot approvals are GA and off by default. They count toward required approvals, can be limited to chosen paths, and are dismissed by any new commit.
  • ReviewBench is GitHub's own benchmark, with known caveats. Judge review quality on your own PRs, and keep human owners on sensitive paths.
