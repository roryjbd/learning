Until 2026, GitHub Copilot was several separate tools: code completion in the editor, a chat panel, an agent mode, and a cloud agent that opened pull requests. Each had its own settings, model picker and place to find your work.

GitHub Universe 2026 ran on 28 and 29 October in San Francisco. Most of the Copilot announcements, dated 28 October in the changelog, connect those tools so that Copilot covers more of the process of delivering a change: planning work across repositories, writing the code, reviewing it, fixing CI failures and merging the pull request. GitHub describes this as moving from a coding assistant to a "software delivery system".

This lesson lists the announcements and their status. The rest of the topic covers each area in turn.

Key point Each announcement handles one step of a change's life: choosing models, running agents, coordinating several agents, reviewing, merging, or running jobs on a trigger.

The steps Copilot now covers

Take one piece of work, for example "add rate limiting to the public API", which touches several repositories:

  1. PlanA Copilot Project collects the repos, design notes and Slack threads involved, and assigns the work to agents.
  2. Choose modelsCopilot Fusion decides which model, or combination of models, handles each step.
  3. Do the workAgents run in cloud sandboxes or locally, on one shared harness. You can follow a session from VS Code, your phone or the web.
  4. ReviewCopilot code review reviews the pull request. A new multi-agent Max level is available, and Copilot can now approve.
  5. MergeAgent Merge watches the PR and fixes failing checks and merge conflicts.
  6. RepeatAutomations and Agentic Workflows run jobs like this on a schedule or an event.

Three recurring changes

You choose effort, not a model

Previously you chose a model from a list. With Fusion, you choose an effort level (Standard, High or Max) and Copilot chooses the models. Code review works the same way: Lite, Balanced and Max are effort levels, not model names.

Agents run without you present

Sessions now run in the cloud or in a background process, and the same live session can be opened in VS Code, the Copilot app, GitHub Mobile, github.com or Copilot CLI. Agent Merge and Automations go further: they start on an event, such as a failed CI run or a schedule, with no prompt from anyone.

More controls for organisations

Shared Automations belong to the repository, so they keep running when their creator leaves. GitHub Enterprise now includes Copilot access. Admins get policies to cap review effort, restrict Fusion's models and disable computer use.

Warning Many Universe write-ups are third-party summaries, and some disagree with GitHub on which features are GA. The statuses in this topic were checked against GitHub's changelog entries from 28 October. When a summary disagrees with the changelog, use the changelog.

What this means in practice

For developers, more of the routine work on a pull request can be handed to Copilot: rerunning flaky CI, fixing a lint failure, or resolving a conflict after someone else merges. For team leads, the main questions are cost and control. Nearly every new feature spends AI credits, and several run agents with no person involved. You need to know which policies exist and which features are on by default.

Takeaways

  • Universe 2026 (28–29 October) extended Copilot to cover planning, building, reviewing and merging a change.
  • Fusion, cloud sandboxes, Agentic Workflows and code review approvals are generally available. Projects, code review Max, computer use and connectors are in preview.
  • In both Fusion and code review, you now choose an effort level rather than a model.
  • Sessions continue after your editor window closes and can be opened from any client. Some agents start on events, with no prompt.
  • Many of the new controls are for admins: repo-owned automations, model policies, effort caps and Enterprise-included access.
