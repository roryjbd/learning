For most of its life, GitHub Copilot was something that sat in your editor and guessed the next line. Then it gained a chat panel, then an agent mode, then a cloud agent that opened pull requests while you did something else. Each step was useful, but they arrived as separate products with separate settings, separate model pickers and separate places to look for your work.

GitHub Universe 2026 ran on 28 and 29 October in San Francisco, and most of the Copilot announcements, dated 28 October in the changelog, were about joining those pieces up. The pitch GitHub and most commentators settled on was that Copilot is moving from a coding assistant to a software delivery system: something that plans work across repositories, writes the code, reviews it, fixes the CI failures and gets the pull request merged.

This lesson is the map. The rest of the topic takes each area in turn.

Key idea Universe 2026 wasn't one big feature. It was a set of pieces that cover the whole loop: choose the model, run the agent anywhere, coordinate many agents, and close out the pull request. Read every announcement as "which step of the loop does this own?"

The loop Copilot now covers

It helps to picture a single piece of work, say "add rate limiting to the public API", and follow it through:

  1. PlanA Copilot Project gathers the repos, design notes and Slack threads involved, and splits the goal into agent tasks.
  2. Pick the modelCopilot Fusion decides which model, or combination of models, handles each step.
  3. Do the workAgents run in cloud sandboxes or locally, on one shared harness, and you can follow a session from your laptop, phone or the web.
  4. ReviewCopilot code review reviews the pull request, now with a multi-agent Max level, and can approve it.
  5. MergeAgent Merge watches the PR and fixes failing checks and merge conflicts until it can merge.
  6. RepeatAutomations and Agentic Workflows run jobs like this on a schedule or a trigger, for the whole team.

Three themes to listen for

1. Stop picking models, start picking effort

Until now you chose a model from a list. With Fusion, you choose how hard Copilot should try (Standard, High or Max) and it decides which models do the work. Code review gained the same idea: Lite, Balanced and Max are effort levels, not model names. Expect this pattern to spread.

2. Agents that keep going without you

Sessions now run in the cloud or in a background process, and you can follow the same live session in VS Code, the Copilot app, GitHub Mobile, github.com or Copilot CLI. Agent Merge and Automations go further and act on events, a red CI run or a schedule, with nobody prompting them.

3. Copilot becomes something your organisation runs

Shared Automations belong to the repository, so they survive someone leaving. GitHub Enterprise now includes Copilot access. Admins get policies to cap review effort, restrict Fusion's models and switch off computer use. These are features for platform teams, not just individual developers.

Read the coverage carefully A lot of the Universe write-ups are third-party summaries, and they disagree on details such as which features are GA. The statuses in this topic were checked against GitHub's own changelog entries from 28 October. When a recap disagrees with the changelog, trust the changelog.

Why it matters for you

If you're a developer, the practical change is that more of the boring parts of a pull request (rerunning flaky CI, fixing a lint failure, resolving a conflict after someone else merges) can now be handed off. If you lead a team, the change is cost and control. Nearly every new capability spends AI credits, and several run agents that act without a human in the loop. Knowing which policies exist, and which features are on by default, is now part of running Copilot well.

The lessons that follow go through the loop in order: Fusion, then the app and the harness, then the pull request features, then automation, and finally a hands-on plan for rolling it all out.

Takeaways

  • Universe 2026 (28–29 October) repositioned Copilot as a delivery system covering plan, build, review and merge.
  • Fusion, cloud sandboxes, Agentic Workflows and code review approvals are generally available. Projects, code review Max, computer use and connectors are in preview.
  • The recurring theme is choosing effort rather than a model, both in Fusion and in code review.
  • Sessions now outlive your editor window and follow you across clients, and some agents run on events with no prompt at all.
  • Many of the new controls are aimed at admins: shared ownership, model policies, effort caps and Enterprise-included access.
