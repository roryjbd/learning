Here's a decision you've probably made a hundred times: you open Copilot Chat, look at the model picker, and wonder whether this task needs the expensive frontier model or whether the fast cheap one will do. Pick the big model for a one-line rename and you've wasted credits. Pick the small one for a tricky concurrency bug and you get a confident wrong answer, then do it again with the big one anyway.

The old Auto option helped a bit by choosing a model for you, but it still picked one model per request and stuck with it. It couldn't say "let the cheap model draft this, and only call the expensive one if the draft looks shaky".

Copilot Fusion is GitHub's answer. It went generally available at Universe on 28 October 2026, on all Copilot plans, in VS Code, the Copilot app, Copilot CLI and JetBrains IDEs. It replaces Auto in the model picker. It grew out of an experiment previously shown as Project HydraFusion.

Key idea Fusion is a router and an orchestrator. It can send a task to one model, or run a small workflow across several, and it only adds model calls when the task needs them. You choose how much effort to spend, not which model to use.

Effort levels, not model names

When you pick Fusion in the model picker, you then choose an effort level:

LevelAimed atSelectable?
StandardEveryday coding. Prioritises versatile modelsYes
HighHarder tasks that need deeper reasoningYes
MaxThe most demanding work, using the most capable pipelinesYes
FastLow-latency use, such as VS Code inline chatNo. Copilot uses it where speed matters

The effort level sets a budget and a quality bar. Within it, Fusion decides what actually runs. Routing can change from one prompt to the next in the same session, so a conversation that starts with "explain this file" and moves on to "now refactor the locking" might use quite different models for each turn.

The three execution patterns

This is the part that makes Fusion more than a smarter Auto. For each task it chooses one of three ways of working:

Single

One model handles the whole task. This is what Auto always did, and it's still the right answer for most simple requests: renaming a variable, writing a docstring, answering "what does this regex do?".

Cascade

An efficient model drafts the answer first. A quality check then either accepts the draft or escalates to a stronger model. Most of the time the cheap draft is fine and you pay cheap-model prices. When it isn't, you get the strong model's answer, without having had to guess in advance.

  1. DraftA fast, efficient model writes a first attempt.
  2. CheckFusion assesses whether the draft meets the bar for this effort level.
  3. Accept or escalateGood enough: return it. Not good enough: hand the task to a more capable model.

Critique

One model drafts, a second model reviews the draft, and the first revises based on the review. Using different models for drafting and reviewing catches mistakes that a single model tends to repeat. Third-party coverage associates Critique mainly with the Max effort level, but GitHub hasn't published an exact mapping of levels to patterns, so treat that as indicative.

Tip If you've ever pasted a model's answer into a second model and asked "what's wrong with this?", Critique is that habit built in. If you've ever tried the cheap model first and switched when it failed, that's Cascade.

What Fusion looks at

Fusion's routing decision takes into account the task itself and, according to GitHub's documentation, real-time system health and availability. If a provider is degraded, Fusion can steer around it rather than leaving you staring at a spinner.

Routing always happens in the cloud. Support for local models is experimental, and even when a local model does some of the work, the routing decision is still made by GitHub's service, so a Fusion session isn't an offline session.

What it costs

Since June 2026, Copilot usage has been billed in AI credits. Fusion doesn't add its own surcharge: you pay each model's standard rate for the work that model does. A Cascade that accepts the cheap draft costs only the cheap call. One that escalates costs both calls.

That means the effort level is also a cost lever. Max may run several models on one task, so it can cost noticeably more per request than Standard. For a limited launch period, paid Copilot plans get a 30% discount on model costs when using Fusion. Coverage disagrees about exactly when the discount ends, so check the changelog if you're planning around it.

SituationSensible effortWhy
Boilerplate, renames, quick questionsStandardSingle or Cascade usually suffices, and it's cheapest
Debugging a race condition across three servicesHighNeeds deeper reasoning, and the cost is worth it
A security-sensitive migration you'll ship todayMaxCross-model critique is worth paying for when mistakes are expensive

Controls for admins

Fusion respects the model policies you already have. If your enterprise or organisation has disabled a model, Fusion won't route to it. That's the main lever if your legal team has approved some providers and not others. Admins can also set a default effort level for their users.

Gotcha Restricting models also restricts Fusion's options. If you lock an organisation down to a single model, Cascade and Critique have nothing to escalate to or critique with, and Fusion behaves much like the old single-model picker. Allow at least an efficient model and a strong model if you want the patterns to work.

When to still pick a model yourself

Fusion is the default, but explicit model choices are still in the picker. Pick a specific model when you need reproducibility (comparing outputs over time, writing an evaluation), when a particular model has a capability you rely on, or when you're debugging a prompt and don't want the router changing two things at once.

Takeaways

  • Copilot Fusion is GA on all plans and replaces Auto in the model picker across VS Code, the Copilot app, CLI and JetBrains.
  • You choose an effort level (Standard, High or Max). Fast exists for low-latency spots like inline chat but isn't selectable.
  • Fusion runs one of three patterns per task: Single, Cascade (draft then escalate if needed) or Critique (draft, review, revise).
  • You pay each model's normal rate for the work it does, with a limited-time 30% discount on paid plans. Higher effort can mean more model calls and more credits.
  • Org and enterprise model policies limit which models Fusion may use, and admins can set a default effort level. Local models are experimental, and routing stays in the cloud.
