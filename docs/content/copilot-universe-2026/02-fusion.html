Before Fusion, you chose a model for each request. A large model costs more credits. A small model is more likely to get a hard task wrong, and then you pay again to rerun it on a larger one. The Auto option chose a model for you, but it still sent each request to a single model.

Copilot Fusion replaces Auto in the model picker. It became generally available on 28 October 2026 on all Copilot plans, in VS Code, the Copilot app, Copilot CLI and JetBrains IDEs. It combines Auto's model selection with the multi-model orchestration from GitHub's research preview, Project HydraFusion. You choose an effort level, and Fusion decides which models to use.

GitHub reports that on the Artificial Analysis Coding Agent Index, Fusion Max scored 60, within two points of Claude Code with Opus 5.5 Max, at about half the average API cost per task and with about 40% less time per task. This is GitHub's own result.

Key point Fusion routes each prompt to one model, or runs a short workflow across several. It only adds model calls when the task needs them. You choose how much effort to spend, not which model to use.

Effort levels

After selecting Copilot Fusion in the model picker, you choose an effort level:

LevelGitHub's descriptionSelectable
StandardPrioritises versatile models for everyday codingYes
HighPrioritises capable models for harder tasks and deeper reasoningYes
MaxPrioritises the most capable models for the most demanding tasksYes
FastUsed only where fast models are needed, in VS Code inline chatNo

The effort level sets a quality bar. Within it, Fusion decides what runs. Routing can change from one prompt to the next in the same session. For example, "explain this file" and "now refactor the locking" may use different models.

Execution patterns

For each prompt, Fusion uses one of three patterns.

Single

One model completes the task. This is what Auto always did, and it suits most simple requests, such as renaming a variable or explaining a regular expression.

Cascade

An efficient model drafts a response. A quality check then accepts the draft or passes the task to a stronger model. When the draft is accepted, you pay only for the efficient model. When it isn't, you get the stronger model's answer without having chosen it in advance.

  1. DraftAn efficient model writes a first attempt.
  2. CheckFusion assesses whether the draft meets the bar for this effort level.
  3. Accept or escalateIf it does, the draft is returned. If not, a more capable model takes the task.

Critique

One model drafts a response and other models review it. GitHub's docs describe several models reviewing in parallel, with their feedback combined before the drafting model revises. Different models tend to catch mistakes that a single model repeats.

Cascade and Critique take longer than Single because they make extra model calls. Which pattern runs depends on the effort level and the task. After a response, hover over the effort level name below it to see which models were used.

Other inputs to routing

GitHub's docs say Fusion also takes real-time system health and availability into account, so it can avoid a degraded provider.

Fusion can also route to local models, in an opt-in experimental preview. On supported Windows devices, the Copilot app can download and manage a local model (MAI Code 1.1 Flash). Copilot CLI can also use manually configured local models on Windows, macOS and Linux. Fusion only considers local models at the Standard effort level.

Limit Routing decisions are always made in GitHub's cloud, so a Fusion session that uses a local model still needs a network connection. GitHub also notes that local models may have different safety protections from Copilot's cloud models.

Cost

Since June 2026, Copilot usage has been billed in AI credits. Fusion has no surcharge: each model it uses is billed at that model's standard rate. A Cascade that accepts the first draft costs one efficient call. One that escalates costs both calls.

So the effort level also affects cost. Max may run several models on one task, so a Max request can cost more than a Standard one. For a limited time, paid plans get a 30% discount on model costs when using Fusion. GitHub's JetBrains release notes say this lasts for the first 30 days, which puts the end at around late November 2026.

Admin controls

Fusion only uses models enabled in your enterprise and organisation model policies. If your legal team has approved some providers and not others, this is the control to use. Enterprise admins can see which models Fusion picks from, and can disable a model for Fusion only without disabling it for everyone.

Admins can also make Copilot Fusion, at any effort level, the default model for their users through enterprise managed settings.

Warning Restricting models also restricts Fusion. If an organisation allows only one model, Cascade and Critique have no other model to use, and Fusion behaves much like a single-model picker. If Fusion Max is missing from the model picker, GitHub's docs say one of the models it needs is probably disabled.

When to choose a model yourself

Specific models are still in the picker. Choose one when you need reproducible results (for example, comparing outputs over time or writing an evaluation), when you rely on one model's particular capability, or when you're debugging a prompt and don't want the routing to change at the same time.

Takeaways

  • Copilot Fusion is GA on all plans and replaces Auto in VS Code, the Copilot app, Copilot CLI and JetBrains.
  • You choose Standard, High or Max. Fast is used only in VS Code inline chat and can't be selected.
  • Fusion runs one of three patterns per prompt: Single, Cascade (draft, then escalate if needed) or Critique (draft, review, revise).
  • Each model used is billed at its standard rate, with a 30% discount on paid plans for the first 30 days. Higher effort can mean more model calls.
  • Model policies limit which models Fusion can use, and admins can make Fusion the default. Local models are experimental, used only at Standard, and routing stays in the cloud.
