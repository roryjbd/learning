Imagine you kick off an agent in VS Code to upgrade a test framework across a large repo. It'll take forty minutes. You close the laptop to catch the train, and the agent dies with the editor window. Or it keeps running in the cloud, but the only way to check on it is a different web page that shows the session differently from your editor, with a different set of custom instructions loaded.

That fragmentation was the problem behind a cluster of Universe 2026 announcements. Agents now run on one shared harness wherever they start, sessions can outlive the window that started them, and you can follow the same live session from any Copilot client. On top of that, the Copilot app gained Projects, which coordinate many agents across many repositories.

Key idea A session is no longer tied to the client you started it in. One harness runs it, a background host or the cloud keeps it alive, and any client can attach to it.

The harness: one agent brain everywhere

The harness is the agent loop itself: the code that takes your prompt, calls the model, runs tools, edits files and decides when it's done. Until now, VS Code's local agent and Copilot CLI had separate harnesses, which is why a custom agent or instruction file could behave slightly differently in each.

At Universe, GitHub combined them. The Copilot harness is now the default for new sessions in VS Code's editor and its Agents window, and the same harness is now the default in JetBrains IDEs where it's available. Because it's the same harness, your agent customisations carry across VS Code, Copilot CLI and the Copilot app.

The harness is built on the Microsoft Copilot SDK, which is the new name for the GitHub Copilot SDK. The SDK went GA in June 2026 in six languages (Node.js/TypeScript, Python, Go, .NET, Rust and Java). The rename reflects that it's becoming the shared agent foundation behind both Microsoft and GitHub products. It's happening in phases. The repo is moving to the Microsoft organisation, and branding and docs are being updated, but existing package names and namespaces may keep referring to the GitHub Copilot SDK during the transition.

Gotcha Don't rush to rename imports in code that uses the SDK. GitHub says no immediate changes are required for existing users, and support stays the same. Watch the changelog for any actual package change.

Agent Host: sessions that survive the window

In VS Code, the new Agent Host runs agent sessions in a separate process from the editor window. Close the window, or the folder, and the session keeps going. Reopen VS Code and you're back in it.

It also works on another machine. VS Code's Remote SSH and dev tunnels now extend to the Agents window, so an agent can run on, say, a beefy dev box and keep going when you disconnect. To control agents on a machine from GitHub Mobile, run this from the project folder on that machine:

code agent host --github-environment

The catch is obvious but easy to forget: the remote machine, and the Agent Host on it, have to stay running. Shut the lid on the dev box and the session stops.

GitHub also published the Agent Host Protocol 1.0, an open protocol that lets third-party clients join live sessions. Client libraries are listed for TypeScript, Rust, Go, Kotlin and Swift. If you've wanted to build your own dashboard or bot that watches agent sessions, this is the supported route.

The cloud: sandboxes and session continuity

For work you don't want on any machine of yours, cloud sessions run in cloud sandboxes, and every cloud session now runs in a sandbox by default. The new connected cloud experience and cloud sandboxes are generally available on paid Copilot plans. Sandboxes start fast, have no one-hour limit on total running time, and save a snapshot when they shut down, so you can resume the session later from any client.

Billing for sandbox usage starts in November 2026 and draws from your included Actions entitlement. That entitlement is now a single dollar-based pool, rather than a fixed number of runner minutes, shared between GitHub-hosted runners, cloud sandboxes and, on Team and Enterprise Cloud, larger hosted runners. Agent sessions and your CI builds now spend from the same pot. Access to the cloud experience is controlled by a Copilot setting called "Copilot in the cloud".

The headline feature is session continuity. You can start a cloud session in VS Code's Agents window and pick it up in the Copilot app, GitHub Mobile, github.com or Copilot CLI. All of them show the same live session and stay in sync. GitHub also lists Slack and Microsoft Teams among the surfaces of the cloud experience.

  1. StartAt your desk, in VS Code's Agents window: "upgrade the test framework".
  2. LeaveThe session runs in a cloud sandbox. Your laptop can sleep.
  3. Check inOn the train, open GitHub Mobile, see that it's stuck on a config question and answer it.
  4. FinishBack home, open the Copilot app or the CLI, attached to the same session, and review the diff.

The Copilot app and Projects

The GitHub Copilot app is a desktop app (Windows, macOS and Linux) that acts as a home for agent work. It launched in technical preview in May 2026 and was opened to all Copilot plans in June. Each session gets its own git worktree, branch and task state, so several can run in parallel without treading on each other.

The big Universe addition is Projects, in public preview. A project brings together everything a piece of work touches: multiple repositories, design mocks, Slack discussions, meeting notes and other context. You give it a goal, choose the models and tools, and Copilot runs as many agents as the work needs. It brings back results for your review, usually pull requests across several repos, and tracks progress in one place. Projects can also cover work that isn't code at all, like a launch plan, and can have their own project automations for repeat tasks. For a focused task in one repository, you can still start a plain session.

Take "add rate limiting to the public API" from the first lesson. That touches the gateway repo, a shared middleware library and the docs site. A project lets one goal fan out to three agents and shows you all three in one place.

Watch your reviewers Analysts quoted in the launch coverage made a fair point: ten parallel agents can mean ten pull requests that someone has to review, test and merge. Projects move the bottleneck from writing code to reviewing it, which is why the next lesson's review and merge features matter.

Connectors and computer use

Two more previews round this out.

  • Copilot connectors are GitHub-verified MCP servers, in public preview on all Copilot plans. You pick a service and sign in, with no server to find, nothing to install and no credentials to manage. One connection works across the Copilot app, Copilot CLI, VS Code, Copilot in the cloud and GitHub Mobile. There are 26 services at launch, including Slack, Figma, Notion, Sentry, Linear, Atlassian Rovo, Cloudflare and Vercel. On Business and Enterprise, an admin has to enable the Editor preview features policy, and add the verified servers to any MCP allowlist.
  • Computer use lets Copilot read app content, click controls, type and move between desktop apps on macOS and Windows, including apps with no API or CLI. It's in public preview in the Copilot app and experimental in VS Code. It's off until you turn it on (in the app, Settings > Computer Use), Copilot asks for approval before controlling each app, and organisations can disable it through managed settings.

Takeaways

  • VS Code, Copilot CLI, the Copilot app and (soon by default) JetBrains share one Copilot harness, so customisations behave the same everywhere.
  • The harness is built on the Microsoft Copilot SDK, the renamed GitHub Copilot SDK. The rename is phased, and existing users don't need to change anything yet.
  • VS Code's Agent Host keeps sessions alive after the window closes and can run on a remote machine, as long as that machine stays on. Agent Host Protocol 1.0 lets other clients join sessions.
  • Cloud sessions run in sandboxes, GA on paid plans. Sandbox usage is billed from November 2026 out of the shared Actions entitlement, and one live session can be followed from VS Code, the app, Mobile, github.com or the CLI.
  • Projects (public preview) coordinate agents across repos and context sources. Connectors are verified MCP servers in public preview, and computer use is a preview that you have to turn on.
